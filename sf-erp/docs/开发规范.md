# ERP 开发规范

> 所有并行任务（包括 AI 生成的代码）必须遵守本规范。有疑问以"业界主流 + 本文档"为准。

## 1. 后端规范（Java / Spring Boot）

### 1.1 模块与依赖
- 业务代码只写在**自己的模块**内；公共能力下沉 `erp-common`（纯 Java）/ `erp-framework`（技术栈）。
- 依赖方向单向：`common ← framework ← system ← basedata ← {purchase, sales, inventory, mrp} ← finance ← server`，**禁止反向依赖、禁止循环依赖**。
- 跨模块只调对方暴露的 Service 接口，不直接查别人的表。

### 1.2 分层约定（每个业务模块内）
```
com.erp.<module>
├── controller/   # 参数接收+校验+组装响应；禁止业务逻辑
├── service/      # 接口 + impl；业务逻辑、事务边界都在这
├── mapper/       # MyBatis-Plus Mapper；复杂 SQL 写 XML 到 resources/mapper/<module>/
├── entity/       # 数据库表映射（继承 BaseEntity）
└── dto/          # request 查询对象 / form 提交对象 / vo 响应对象
```
- Entity **禁止**直接作为新增/修改接口的入参，用 form 对象承接（防 mass assignment）。
- 出参用 VO，控制字段暴露（如密码永不返回）。

### 1.3 REST API
- 资源复数名词 + HTTP 动词：`GET /system/users`（分页）、`GET /system/users/{id}`、`POST /system/users`、`PUT /system/users/{id}`、`DELETE /system/users/{id}`。
- 统一响应 `Result<T>`；分页响应 `PageResult<T>`；参数名 `pageNum/pageSize/keyword`。
- 写操作加 `@Valid` + JSR-303 注解；删除一律逻辑删除（deleted 字段由 MP 处理）。

### 1.4 数据库
- **建表/改表只允许新增 `script/sql/migration/V<N>__<描述>.sql`**，由 Flyway 自动执行；禁止手改库。
- 每表必有：`id BIGINT AUTO_INCREMENT`、`create_by/create_time/update_by/update_time/deleted`。
- 命名：表 `模块前缀_业务名`（sys_user / pur_order / sal_order / inv_stock / fin_voucher / mrp_bom）；列蛇形命名。
- 金额：`DECIMAL(18,2)`，**禁止 float/double**；数量 `DECIMAL(18,4)`。
- 枚举状态列配 COMMENT 注明取值；高频查询条件加索引；唯一约束显式建 uk_ 索引。

### 1.5 事务与并发
- 涉及多表写入/库存增减/金额计算必须 `@Transactional(rollbackFor = Exception.class)`。
- 库存增减用条件 UPDATE（`stock = stock + ? WHERE ...`）或乐观锁，防超卖。
- 单号生成：`模块前缀 + yyyyMMdd + 4位流水`（Redis 自增），如 `PO202609050001`。

### 1.6 注释要求（用户明确要求"完善"）
- 每个**类**：Javadoc 说明职责、关键约束；每个**公开方法**：Javadoc 含参数/返回/异常。
- 方法内部：只在"为什么这么写"不直观时注释（并发、事务边界、坑），不复述代码。
- 数据库脚本：文件头注释块说明本脚本目的。

### 1.7 安全
- 口令只存 BCrypt；敏感字段（价格成本）按权限过滤返回。
- 所有接口默认需要登录（白名单除外）；横向越权校验数据归属。

## 2. 前端规范（React / TypeScript）

### 2.1 目录
```
src/
├── api/          # 按模块分文件(system.ts/purchase.ts...)，只做请求定义
├── stores/       # zustand 全局状态（登录态/字典缓存）
├── layouts/      # 布局（MainLayout 已含菜单+转场动画）
├── router/       # 路由表集中管理，页面懒加载
├── pages/<模块>/ # 页面组件；列表页参照 system/users/UserList.tsx 模板
└── styles/       # 全局样式与动效工具类
```

### 2.2 约定
- 组件用函数组件 + hooks；请求一律 TanStack Query（`queryKey` 带入参）；不直接 useState 存服务端数据。
- 路径别名 `@/`；组件文件名 PascalCase；hooks `useXxx`。
- TS strict 不许 `any` 上生产代码；接口出参类型与后端 VO 对齐，定义在 api/ 文件内。
- UI：以 AntD 为主；动效用 Framer Motion（入场/转场/微交互），动效保持 0.2~0.4s、ease-out，不喧宾夺主 —— **ERP 场景的信息密度和效率优先**。

### 2.3 视觉风格基线
- 主色 `#1668dc`（ERP 湛蓝），圆角 8，表格/表单高密度布局。
- 指标卡、图表页参照 `pages/dashboard/Dashboard.tsx`（错峰入场 + hover 上浮 + 渐变图表）。
- 新页面必须包含：loading 态（骨架/Spin）、空态、错误兜底。

## 3. Git 规范
- 分支：`main`（可发布）/ `develop`（集成）/ `feature/<模块>-<功能>`。
- Commit（Angular 风格）：`feat(purchase): 采购订单分页查询`；`fix(inventory): 修复负库存校验缺失`。
- 提交前：后端 `mvn -q compile` 通过、前端 `npm run build` 通过；AI 生成代码过一遍 `/code-review`。

## 4. 并行开发协作（AI 多任务）
- 每个业务模块一个并行任务，**只改自己模块目录** + `script/sql/migration/` 新增自己的脚本 + 前端 `pages/<自己模块>/`。
- 公共改动（common/framework/布局/路由表）冲突时由主线程串行合并。
- SQL 脚本版本号按模块错开：basedata 用 V10x、purchase V20x、sales V30x、inventory V40x、finance V50x、mrp V60x；system 用 V1x。
