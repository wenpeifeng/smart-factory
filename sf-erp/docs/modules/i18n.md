# 后端国际化（i18n）模块说明

> 目标：按 Spring MessageSource 标准让后端提示/错误信息支持中英双语，前端（react-i18next）通过
> `Accept-Language` 请求头切换语言，并可依据 `messageKey` 做本地化兜底。

## 1. 总体架构

```
请求（Accept-Language: zh-CN / en / 缺省）
  │
  ├─ DispatcherServlet ──► LocaleResolver(AcceptHeaderLocaleResolver)   [erp-framework I18nConfig]
  │                          zh/zh-CN → zh_CN；en/en-US → en；其余/缺失 → zh_CN
  │
  ├─ Controller / Service 抛 BusinessException（带 messageKey 或字面文案）
  │
  └─ GlobalExceptionHandler / SecurityConfig(401/403)
        │  ErpMessages.getMessage(key, args)          [erp-framework 静态门面]
        │  兜底链：当前 Locale → zh_CN 基准文件 → 调用方默认文案 → key 原样（永不抛错）
        ▼
  MessageSource(ResourceBundleMessageSource, basename=i18n/messages, UTF-8)
        │
        ▼
  classpath:i18n/messages_zh_CN.properties（中文基准） + messages_en.properties
```

## 2. 代码地图

| 位置 | 职责 |
| --- | --- |
| `erp-common/…/i18n/MessageKeys.java` | 消息 key 常量登记处（erp.error.* / erp.biz.*），纯 Java 无 Spring 依赖 |
| `erp-common/…/result/ErrorCode.java` | 错误码枚举新增 `codeKey` 字段（与 MessageKeys 一一对应）；`message` 保留为中文兜底文案 |
| `erp-common/…/exception/BusinessException.java` | 新增 messageKey 构造：`ofKey(key, args…)`、`ofKey(errorCode, key, args…)`、`new BusinessException(errorCode)` 自动携带 codeKey；旧构造（字面文案）全部保留 |
| `erp-common/…/result/Result.java` | 响应体新增 `messageKey` 字段（成功/字面文案时为 null） |
| `erp-framework/…/i18n/I18nConfig.java` | ResourceBundleMessageSource（读 application.yml 的 spring.messages.*）+ AcceptHeaderLocaleResolver（默认 zh_CN），Bean 名固定 `localeResolver` |
| `erp-framework/…/i18n/ErpMessages.java` | 静态门面：按当前请求 Locale 取词 + 中文兜底；安全过滤链场景请传显式 Locale |
| `erp-framework/…/exception/GlobalExceptionHandler.java` | 所有 `Result.message` 走 ErpMessages；BusinessException 有 messageKey 时本地化，否则原样透出 |
| `erp-framework/…/config/SecurityConfig.java` | 401/403 JSON 文案本地化（安全链早于 DispatcherServlet，显式 `localeResolver.resolveLocale(request)`） |
| `erp-bootstrap/src/main/resources/i18n/` | messages_zh_CN.properties（46 条）+ messages_en.properties（46 条），key 完全一致 |
| `erp-bootstrap/src/main/resources/application.yml` | `spring.messages.basename/encoding/fallback-to-system-locale`（唯一事实来源，I18nConfig 读取） |

## 3. key 命名规范

| 前缀 | 用途 | 示例 |
| --- | --- | --- |
| `erp.error.*` | 框架层 / ErrorCode 枚举（codeKey）/ 异常处理器明细 | `erp.error.unauthorized`、`erp.error.missing-param` |
| `erp.biz.*` | 跨模块高频业务提示 | `erp.biz.stock-not-enough`、`erp.biz.period-closed` |
| `erp.<模块>.*`（建议） | 仅单模块使用的文案（如 `erp.inv.*` 库存），避免 MessageKeys 膨胀 | `erp.inv.batch-not-enabled` |

规则：
- 全小写 kebab-case；占位符用 MessageFormat 风格 `{0} {1}`；**英文文案中的单引号必须写成 `''`**（MessageFormat 转义）。
- 两份 properties 的 key 集合必须完全一致；`messages_zh_CN.properties` 是基准语言，英文漏配时自动回退中文，不会报错。

## 4. 新增文案流程（后端）

1. 在 `MessageKeys`（或模块自有常量类）登记 key 常量；
2. 在 `messages_zh_CN.properties` 与 `messages_en.properties` 同步追加中英文（两文件 key 必须一致）；
3. 业务代码抛出：`throw BusinessException.ofKey(MessageKeys.BIZ_PERIOD_CLOSED, "2026-08")`；
   或带错误码：`throw BusinessException.ofKey(ErrorCode.DATA_NOT_EXISTS, MessageKeys.BIZ_DOC_NOT_EXISTS, docNo)`；
4. 无需其他改动 —— GlobalExceptionHandler 自动按请求 Locale 解析并把 `messageKey` 回填进 Result。

存量硬编码中文迁移（进行中）：

```java
// 旧（字面文案，两种语言都返回中文）
throw new BusinessException("库存不足：仓库[%d]物料[%d]...", whId, matId);
// 新（key + 参数，自动中英）
throw BusinessException.ofKey(MessageKeys.BIZ_STOCK_NOT_ENOUGH, whId, matId, qty);
```

注意：`new BusinessException(ErrorCode.X, "文案")` 两参调用仍是"字面文案"语义（兼容存量）；
带 key 请用 `ofKey(...)` 工厂或三参以上构造。

## 5. 前端对接约定（react-i18next）

1. **请求头**：axios 统一拦截器带上 `Accept-Language`（zh-CN / en），后端据此返回对应语言的 `message`。
2. **展示**：正常情况直接展示后端返回的 `message`（服务端已本地化，可直接用）。
3. **本地化兜底（可选）**：错误响应带 `messageKey`（如 `erp.error.unauthorized`），前端资源文件中含同名 key 时优先用前端翻译，未命中再回落 `message`。这样即便后端文案缺失，前端仍可保证界面语言一致。
4. **成功响应**：`messageKey` 为 null（成功文案"操作成功"暂不参与本地化，前端成功提示建议用前端自己的文案）。

## 6. 已知边界与后续迁移

| 项 | 现状 | 计划 |
| --- | --- | --- |
| `Result.ok()` 成功文案 | 枚举默认中文（前端一般不展示后端成功文案） | 如需本地化，成功链路也走 ErpMessages |
| `@Valid/@NotBlank` 等注解 message | 字面中文（如"账号不能为空"），校验失败时前缀已本地化、字段文案仍中文 | 注解 message 改为 `{erp.biz.not-blank}` 风格 key + 校验器接入 MessageSource |
| 业务模块 `new BusinessException("中文…")` | **已完成（2026-09-06）**：788 处全部迁移为 `BusinessException.ofKey("erp.<模块>.<语义>")`，同步登记 zh_CN/en 双语 key | — |
| `@Idempotent`/`@RateLimit` 注解的 message 属性 | 注解配置的字面文案 | 支持填 key，切面改用 ofKey |

## 7. 验证方式（curl）

```bash
# 401：无 token 访问受保护接口 —— zh 缺省中文 / en 英文
curl -s http://localhost:8080/api/auth/me
curl -s -H "Accept-Language: en" http://localhost:8080/api/auth/me

# 404：不存在的路径
curl -s -H "Accept-Language: en" http://localhost:8080/api/no-such-api

# 400：@Valid 校验失败（登录空参）
curl -s -X POST -H "Content-Type: application/json" -H "Accept-Language: en" \
     -d '{"username":"","password":""}' http://localhost:8080/api/auth/login
```
