# ERP 日志规范

> 适用范围：erp-backend 全模块。落地代码：`erp-bootstrap/src/main/resources/logback-spring.xml`、
> `erp-framework/.../log/TraceIdFilter`、`erp-platform-system` 的 OperLog/LoginLog 体系。
> 本文是三类日志的定位、格式与检索指南的唯一事实来源。

## 1. 三类日志总览

| 类别 | 定位 | 存储 | 写入方 | 保留 |
| --- | --- | --- | --- | --- |
| **审计日志**（应用日志） | 关键业务动作的过程留痕：审核/过账/结账/库存变更/成本过账的入口、关键分支拒绝（库存不足/信用超限/借贷不平/透支等）。面向**开发与运维排障**，按 traceId 串联一次请求的完整链路。 | JSON 文件 `logs/erp-backend.json`（+ dev 控制台彩色） | 各业务 Service 内 `log.info` / `log.warn`（@Slf4j） | 30 天滚动归档 |
| **操作日志** | 登录后的**写操作**明细：谁在何时对什么模块做了什么、请求参数、耗时、成败。面向**业务审计/页面查询**。 | MySQL 表 `sys_oper_log`（V14） | Controller 方法标注 `@OperLog(module, operation)` → OperLogAspect AOP 落库 | 只增不改 |
| **登录日志** | 认证链路事件：登录成功/失败（密码错误、账号停用）/账号锁定/登出，含 IP、UA、耗时。面向**安全审计**（撞库、暴力破解取证）。 | MySQL 表 `sys_login_log`（V1031） | AuthServiceImpl 发布 `LoginLogEvent` → LoginLogListener 落库（Spring 事件解耦） | 只增不改 |

三者互补：操作日志回答"登录后做了什么"，登录日志回答"谁在何时从哪里登录"，审计日志回答"这一次请求内部每一步发生了什么"。

## 2. 审计日志（应用日志）

### 2.1 输出格式

- **dev profile**：控制台彩色可读，文件同 JSON。
  ```
  2026-09-06 00:53:49.716  INFO [c1919b4e405a4949] [t:1000 u:1] [nio-8080-exec-6] c.e.p.s.impl.PurInstockServiceImpl : [采购入库][审核] 开始 单号id=20 操作人=1
  ```
  pattern：`时间 级别 [traceId] [t:租户 u:用户] [线程] logger : 消息`
- **prod / 默认 profile**：控制台与文件均为 JSON（logstash-logback-encoder 8.1）。
  ```json
  {"timestamp":"2026-09-06T00:53:49.773+08:00","message":"[成本][入库过账] 物料=4 业务=PUR_IN 单号=RK202609060001 数量=1 金额=0.20 单价=0.200000 结存数量=1909 结存金额=286.40","logger":"com.erp.cost.service.impl.CostLedger","thread":"http-nio-8080-exec-6","level":"INFO","traceId":"c1919b4e405a4949","tenantId":"1000","userId":"1","orgId":"1","app":"erp-backend"}
  ```

### 2.2 JSON 字段规范

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `timestamp` | logback | ISO-8601 东八区，毫秒 |
| `level` | logback | INFO / WARN / ERROR / DEBUG |
| `traceId` | MDC | 16 位十六进制，请求内唯一（TraceIdFilter 生成，请求头可透传） |
| `tenantId` / `orgId` / `userId` | MDC | JwtAuthFilter 令牌解析成功后写入；未登录请求（如 /auth/login）缺省 |
| `logger` / `thread` | logback | 打点类 / 线程名 |
| `message` | 业务代码 | 见 2.4 消息格式 |
| `stackTrace` | logback | 异常堆栈（root-cause-first，截断 8K，框架噪音已排除） |
| `app` | 固定 | `erp-backend`（多应用采集时区分来源） |

MDC 键名常量收口在 `com.erp.framework.log.MdcKeys`，改键名必须同步 logback-spring.xml 与本文。

### 2.3 文件落盘与滚动

- 路径：`logs/erp-backend.json`（相对启动目录；start-all.sh 以仓库根启动 → 仓库根 `logs/`），
  由 `application.yml` 的 `logging.file.path: logs` 注入。
- 滚动：按天 + 单文件 100MB（先到为准），压缩为 `logs/archive/erp-backend.{yyyy-MM-dd}.{i}.json.gz`，
  保留 30 天 / 总量上限 10GB，启动时自动清理过期归档。
- 写文件走 AsyncAppender（队列 2048，任何级别不丢弃，队列满阻塞不丢日志）。
- 级别策略（logback-spring.xml 内维护，**禁止在 yml 配 logging.level**，会覆盖 profile 分级）：
  - dev：`com.erp` DEBUG（MyBatis Slf4jImpl 逐条打印 SQL，便于排查慢 SQL）；`org.apache.ibatis` WARN。
  - prod/默认：`com.erp` INFO；`org.apache.ibatis` / `com.baomidou` / `org.mybatis` WARN（SQL 不再逐条输出）。

### 2.4 业务打点规范（为什么记，不是每行都记）

消息统一格式：`[模块][动作] 结果 关键参数键=值 ...`，例如：

- 入口行（INFO）：`[采购入库][审核] 开始 单号id=20 操作人=1`
- 完成行（INFO）：带结果三要素（单号/数量/金额），如 `[采购入库][审核] 完成 单号=RK... 订单=PO... 明细数=1 总数量=1 总金额=0.20 应付单已生成 操作人=1`
- 拒绝行（WARN）：`原因=库存不足` / `原因=信用额度不足` / `原因=借贷不平衡` / `原因=余额不足` 等，携带缺口值便于对因。

记录原则（遵循"注释规范：为什么记"）：

1. **写账动作必须记**：任何落库存/成本/应收应付/凭证/账户余额的方法，入口 + 完成各一行 INFO。
2. **拒绝分支必须记 WARN**：库存不足、信用超限、借贷不平、透支/核销超额、质检卡点、已结账期间补录——这些是业务对不上时的第一排查入口。
3. **查询不记**：page/detail 等只读方法不打点，避免噪音。
4. **参数带单号不带敏感信息**：不记密码、令牌、完整请求体；数量金额用 `toPlainString()`。
5. 操作人：消息里显式带 `SecurityUtils.getCurrentUserId()`，且 MDC `userId` 随每行日志自动携带（双保险，日志文件里 grep 任意一个都能定位人）。

已覆盖的关键 Service（写账动作 + 拒绝分支）：
`PurInstockServiceImpl`（审核）、`SalOrderServiceImpl`（审核+信用校验）、`SalOutstockServiceImpl`（审核）、
`StockServiceImpl`（入库/出库/变动 + 库存不足拒绝）、`CostLedger`（入库/出库过账 + 结存不足/已结账期间拒绝）、
`CostSettleServiceImpl`（结账 + 重复/倒挂拒绝）、`FinVoucherServiceImpl`（凭证新增/过账 + 借贷不平）、
`FinPaymentServiceImpl`（付款核销 + 核销超额/透支拒绝）、`MrpWorkOrderServiceImpl`（下达/完工入库/关闭 + 质检卡点/超量拒绝）。

## 3. 链路追踪（traceId）

- `TraceIdFilter`（erp-framework，`Ordered.HIGHEST_PRECEDENCE`，先于 Spring Security/JWT 过滤器执行）：
  - 请求头带合法 `X-Trace-Id`（8~64 位 `[A-Za-z0-9_-]`）→ 沿用（网关/前端/上游服务透传）；非法值丢弃重生成（防日志注入）。
  - 响应头必回显 `X-Trace-Id`（含 401/403/500），前端报错时可展示该 ID 直接检索后端日志。
  - 白名单跳过（不分配 traceId 也不回显）：`/ping`、`/actuator/**`、`/v3/api-docs/**`、`/swagger-ui/**`、`/error`。
- `JwtAuthFilter` 认证成功后把 tenantId/orgId/userId 写入 MDC（请求结束精确 remove，不 clear 以免误清 traceId）。

## 4. 操作日志（sys_oper_log）

- 使用方式：Controller 写方法标注 `@OperLog(module = "采购管理", operation = "审核采购入库单")`，
  AOP 切面（OperLogAspect）自动记录：模块、操作、方法、URL、请求参数（JSON，截断 2000）、
  操作人（id+账号）、IP、耗时、成败、异常信息。
- 约束：日志落库失败只 warn 不影响业务；登录接口虽在白名单也标注了 @OperLog，但登录场景请优先看登录日志。
- 查询接口：`GET /system/logs`（分页，支持 module/operatorName/status/时间段过滤）。

## 5. 登录日志（sys_login_log）

- 记录事件：登录成功、密码错误（含剩余次数）、账号停用、**第 5 次失败触发锁定**、锁定期内尝试、登出。
- 字段：账号、用户 ID、事件（LOGIN/LOGOUT）、结果、失败原因、IP（优先 X-Forwarded-For）、UA（截断 500）、耗时（含 BCrypt 校验）、租户、时间。
- 实现方式：AuthServiceImpl 发布 `LoginLogEvent`（Spring 事件）→ `LoginLogListener` 同步监听落库 + 打一行
  `[登录日志]` 应用日志（成功 INFO / 失败 WARN）。认证主流程不依赖日志表，落库失败不影响登录。
- 查询接口：`GET /system/login-logs`（分页，支持 username/event/status/ip/时间段过滤）。

## 6. 检索指南

按三个维度检索，任选其一：

### 6.1 按 traceId（一次请求的完整链路）

```bash
# 前端/调用方从响应头 X-Trace-Id 拿到 ID 后：
grep 'c1919b4e405a4949' logs/erp-backend.json            # JSON 文件（dev 与 prod 均落盘）
grep 'c1919b4e405a4949' script/logs/backend.log           # dev 控制台历史
# 只看业务链路、排除 SQL DEBUG：
grep 'c1919b4e405a4949' logs/erp-backend.json | grep -v '"level":"DEBUG"'
# jq 结构化过滤（ERROR 行 + 堆栈）：
grep '"traceId":"c1919b4e405a4949"' logs/erp-backend.json | jq 'select(.level=="ERROR")'
```

一次采购入库审核的典型链路（同一 traceId ≥3 行）：
`[采购入库][审核] 开始` → `[库存][入库]` → `[成本][入库过账]` → `[采购入库][审核] 完成`。

### 6.2 按单号（跨请求追溯一个业务单据）

```bash
grep 'RK202609060002' logs/erp-backend.json        # 该入库单的创建/审核/库存/成本全部动作
docker exec erp-mysql mysql --default-character-set=utf8mb4 -uroot -p erp_db \
  -e "SELECT * FROM sys_oper_log WHERE request_params LIKE '%20%' AND module='采购管理';"
```

### 6.3 按用户（谁在什么时候做了什么）

```bash
grep '"userId":"1"' logs/erp-backend.json          # 应用日志（JSON 含 MDC userId）
grep 'u:1]' script/logs/backend.log                # dev 控制台格式
curl -H "Authorization: Bearer $TOKEN" 'http://localhost:8080/api/system/login-logs?username=admin'    # 登录史
curl -H "Authorization: Bearer $TOKEN" 'http://localhost:8080/api/system/logs?operatorName=admin'      # 操作史
```

### 6.4 按告警级别（快速定位异常）

```bash
grep '"level":"WARN"' logs/erp-backend.json | grep -E '库存不足|信用额度|借贷不平|余额不足|锁定'   # 关键拒绝事件
grep '"level":"ERROR"' logs/erp-backend.json | tail -20
```

## 7. 已知注意事项

1. **MyBatis-Plus 租户插件 + `LIMIT ... FOR UPDATE` 组合会产生非法 SQL**（FOR UPDATE 被重写至 ORDER BY 之前）。
   手写锁查询请参照 `CostFlowMapper.selectLastForUpdate` 的子查询包装写法，不要在顶层同时使用 LIMIT 与 FOR UPDATE。
2. 日志级别只能改 `logback-spring.xml`；`application.yml` 出现 `logging.level.*` 会整体覆盖 profile 分级。
3. `logs/` 与 `script/logs/`（启动脚本 nohup 输出）是两个目录：前者是本规范的结构化日志，后者仅是进程控制台重定向。
4. 登录失败 5 次锁定 10 分钟（Redis `login:fail:{tenantId}:{username}`），验证锁定行为请用测试账号，避免锁死 admin。
