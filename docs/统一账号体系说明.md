# 统一账号体系与系统接入规范

> 套件级权威文档：描述 sf-auth 与业务系统（sf-erp / sf-mes，及未来新系统）之间的用户体系关系。
> 子系统文档与本文件冲突时，以本文件为准。

## 1. 核心模型：物业门禁

**人员（主账号）只在一个地方创建和维护——sf-auth 统一认证中心。** 业务系统不建人、不改人，只保留"已分配到本应用的用户"的本地副本，用于登录匹配和挂本系统内部的角色/权限。

```
                sf-auth 认证中心（唯一事实源）
                idm_user：主账号生命周期
                （入职 / 转岗 / 离职 / 改密 / 禁用）
                          │
        ┌─────────────────┼─────────────────┐
        ▼                 ▼                 ▼
   app_user_assign    app_user_assign    app_user_assign   ← 进门权：谁能进哪个应用
        │                 │                 │
        ▼                 ▼                 ▼
   sf-erp 本地副本    sf-mes 本地副本    未来新系统副本      ← sys_user（同步/JIT 生成，
   （登录匹配 +       （登录匹配 +                          不手工维护）
    ERP 内部角色权限）  MES 内部角色权限）
```

职责边界一句话：

| 管 什么 | 在哪管 |
|---|---|
| 人（账号、姓名、工号、状态、密码）、能进哪个应用 | **只在 sf-auth** |
| 某人进本系统后是什么角色、能看哪些菜单/按钮/数据 | **在各业务系统**（本地角色权限，挂在本地副本上） |

## 2. 登录账号唯一性

登录账号（username）在**认证中心内按租户唯一**（`idm_user` 的 `uk_idm_user_username (tenant_id, username)` 约束）。因为业务系统的账号全部来自认证中心的同步副本，唯一性由源头天然保证，业务系统不需要、也不应该自建账号。

**套件账号命名规范**（本地演示环境，密码统一 `123456`）：

| 系统 | 管理员账号 | 说明 |
|---|---|---|
| sf-auth | `admin` | 种子超管；生产环境首登后必须改密 |
| sf-erp | `erp_admin` | ERP 本地超管副本 |
| sf-mes | `mes_admin` | MES 本地超管副本 |

命名规则 `系统标识_admin`，接入新系统时照此执行（如 `wms_admin`），避免三库 admin 重名无法区分审计日志。

## 3. 业务系统如何拿到用户副本

统一约定：**本地 `sys_user` 表是只读副本**，来源只有两种方式，均以**工号（employee_no）**为关联键：

### 方式 A：同步拉取（推荐，MES / ERP 已实现）

MES 提供 `POST /api/integration/auth/sync` 服务间接口，管理端页面点「同步认证中心用户」触发：
从 auth 拉取已分配到本应用的账号，本地有则更新、无则插入、auth 侧已禁用/离职则本地禁用（软删除，不物理删）。MES 管理端对副本只允许**禁用/启用**（本应用粒度），不允许增删改用户主档案。

### 方式 B：SSO 首登 JIT 建档（ERP 已实现）

用户走 OIDC 统一登录（授权码 + PKCE）首次进入业务系统时，系统用工号匹配本地副本；匹配不到则即时建档（`username = employee_no`，随机密码占位，仅 SSO 可登录）。零依赖定时同步，新分配用户首登即可用。

### 登录双通道与降级

- **主通道：SSO**。登录页跳 auth 统一登录页（http://localhost:5174），回调配发的应用各自处理令牌。
- **降级通道：本地账密**。仅当认证中心不可达时使用（如 `erp_admin` / `mes_admin` 本地直登），恢复后应回到 SSO 主通道。

## 4. 接入新系统的标准动作

后续任何系统（WMS、OA、看板……）接入本套件，按同样方式处理：

1. **auth 侧注册应用**：`app_client` 建客户端（client_id/secret/回调地址），`app_user_assign` 控制进门权；
2. **新系统侧**：以 OIDC 客户端接入（授权码 + PKCE，JWKS 验签），实现 SSO 回调；本地建 `sys_user` 副本表（含 `employee_no` 列），实现「同步拉取」或「JIT 建档」其一（推荐同步拉取，管理体验更好）；
3. **用户管理入口锁死**：新系统的用户管理页面只提供「同步认证中心用户」+「本应用内禁用/启用」，不提供本地新建/编辑/删除用户；
4. **本地角色权限自管**：角色、菜单、按钮、数据权限表挂本地副本；
5. **管理员账号**：`系统标识_admin / 123456`（演示环境）。
