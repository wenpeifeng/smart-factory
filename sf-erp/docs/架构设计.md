# ERP 系统架构设计

> 版本：v1.0（2026-09-05） · 技术基线：Java 21 / Spring Boot 3.3 / React 18 / TS 5.5

## 1. 架构选型结论

**模块化单体（Modular Monolith）**，不做微服务。

理由（调研结论）：
1. 成熟开源 ERP（Odoo/ERPNext/金蝶/用友）全部是单体或模块化单体 —— ERP 的本质是**强事务的流程引擎**（单据 → 库存 → 财务），跨库分布式事务是自找的复杂度；
2. GitHub 上 Spring Cloud 微服务 ERP（如 moserp）均已停维，被验证为过度设计；
3. 多模块 Maven 天然支持"按模块并行开发"，团队扩张后可平滑拆分（模块边界即未来服务边界）。

## 2. 后端架构

### 2.1 模块分层图

```
                     ┌──────────────────────────┐
                     │      erp-server          │ 启动聚合（唯一可执行 jar）
                     └──────────────────────────┘
   ┌────────┬────────┼────────┬────────┬───────┴──────┐
   │purchase│ sales  │inventory│ finance│ mrp(生产)    │  业务纵切（互不依赖）
   └───┬────┴───┬────┴────┬────┴───┬────┴──────┬───────┘
       └────────┴────┬────┴────────┴───────────┘
                ┌────┴─────┐
                │ basedata │  基础资料（物料/客商/仓库，被上游共享）
                └────┬─────┘
                ┌────┴─────┐
                │  system  │  基座（用户/权限/组织/字典/日志）
                └────┬─────┘
                ┌────┴─────┐
                │framework │  技术层（Web/Security/MP/Redis/异常）
                └────┬─────┘
                ┌────┴─────┐
                │  common  │  纯 Java 公共库（Result/异常/常量）
                └──────────┘
```

依赖规则：**只能向下依赖**；业务模块之间禁止横向依赖（采购需要库存能力 → 通过 inventory 暴露的 Service 接口，若出现循环倾向则下沉到 basedata）。

### 2.2 关键技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| ORM | MyBatis-Plus | 国内 ERP 事实标准，复杂报表 SQL 可控 |
| 认证 | JWT + Redis 会话态 | 无状态 + 可强制下线 |
| 权限 | RBAC（角色-菜单-按钮） | 对标金蝶/用友权限模型 |
| 建表 | Flyway + script/sql/migration | 统一脚本管理 + 版本可追溯 |
| 文档 | springdoc-openapi | 与 Spring Boot 3 原生集成 |
| 单据流水号 | Redis INCR + 日期前缀 | 高并发不重号（PO20260905xxxx） |

### 2.3 核心领域模型（单据流）

```
销售订单 ──┐                      ┌── 采购入库 ─→ 应付
           ├→ 出库单 → 库存流水 ──┤
销售退货 ──┘       ↑             └── 销售出库 ─→ 应收
                   库存(按 仓库+物料+批次)
采购退货 ──┐       ↓
           ├→ 入库单 → 库存流水 ──┬→ 生产领料
采购订单 ──┘                      └→ 生产入库
                                      ↑
MRP运算: MPS主产计划 × BOM展开 − 现有库存 − 在途 = 建议(采购/生产)
财务: 业务单据 → 应收应付 → 收付款核销 → 总账凭证 → 期末结账
```

**不变量（系统必须守护）**：
- 库存扣减必须行锁/乐观锁，禁止负库存（可配置）；
- 单据状态机单向流转（草稿→已审核→已关闭），禁止跳跃；
- 金额计算全链 DECIMAL，四舍五入规则统一 HALF_UP 到 2 位。

### 2.4 跨模块协作：Service 直调清单（V2101 集成接线）

并行开发期各业务模块按"约定表结构 + 裸 SQL"松耦合协作，2026-09 主线程集成任务（V2101）
把库存/成本/质检/审批四个横切能力切换为 **同 JVM Service 直调**，裸 SQL 通道全部拆除。
依赖方向严格单向：`purchase / sales / mrp → { inventory, cost, qc, workflow }`，
被依赖模块永不反向 import 业务模块代码。

| 调用方 → 被调方 | 调用点 | 方法 | 语义 |
|---|---|---|---|
| purchase → inventory | 采购入库审核 | `StockService.stockIn`（batchNo 透传） | 批次感知入库：批次物料落批次行（缺批次号拒绝），非批次落汇总行 |
| purchase → inventory | 采购退货审核 | `StockService.stockOut`（BATCH/FIFO） | 按原入库批次 BATCH 退回；无批次来源 FIFO/汇总行；不足回滚 |
| sales → inventory | 销售出库审核 | `StockService.stockOut`（FIFO） | 批次物料按 first_in_at 拆批扣减（跨批多行流水）；非批次汇总行 |
| sales → inventory | 销售退货审核 | `StockService.stockIn` | 退货物料回补指定批次行（表单 batchNo） |
| mrp → inventory | 领料/委外发料审核 | `StockService.stockOut`（FIFO） | 同销售出库口径（委外并入 PROD_USE，biz_no=OS 单号可追溯） |
| mrp → inventory | 完工/委外收货 | `StockService.stockIn` | 成品入库（完工表单可带 batchNo） |
| purchase → cost | 采购入库审核 | `CostService.onStockIn`（amount=明细含税金额） | PUR_IN 实时计价（移动加权），cost_flow 即时流水 |
| purchase → cost | 采购退货审核 | `CostService.onStockOut` | PUR_RET 按当前加权价冲减 |
| sales → cost | 销售出库审核 | `CostService.onStockOut` → 回写 `sal_outstock_detail.actual_cost` | SAL_OUT 实际成本，销售毛利统计升级依据（无值回退 ref_cost） |
| sales → cost | 销售退货审核 | `CostService.onStockIn`（amount=null） | SAL_RET 按当前加权价回冲 |
| mrp → cost | 领料/委外发料、完工/委外收货 | `onStockOut` / `onStockIn` | PROD_USE/PROD_IN 实时归集（月结转生产成本/主营业务成本） |
| purchase → qc | 采购入库审核前置 | `QcInspectService.pendingOfSource("pur_instock", id)` | 存在草稿检验单→拒绝（提示单号）；无检验单→免检直过 |
| mrp → qc | 生产完工入库前置 | `pendingOfSource("mrp_work_order", id)` | 同上（FQC 卡点） |
| purchase → workflow | 采购订单审核 | `startFlow("pur_order")` + `isApproved` | 三段式：SKIPPED/AGREED 直过；RUNNING 提示"已提交审批"；通过后再审执行原审核 |
| sales → workflow | 销售订单审核 | `startFlow("sal_order")` + `isApproved` | 同上（vars.amount=订单总额） |
| mrp → workflow | 生产订单下达 | `startFlow("mrp_work_order")` + `isApproved` | 同上（vars.amount=订单数量） |

配套约定：
- 三段式以单据表 `wf_started` 标记区分"首次审核（发起流程）"与"重审（按 isApproved 判定）"，
  单据在流程走完前保持草稿态，不引入"审批中"状态值；被驳回/审批中的草稿允许"关闭"作废；
- 所有审核事务 `audit_by = SecurityUtils.getCurrentUserId()`（未登录上下文 0=系统）；
- 库存调用与成本过账在同一审核事务内（任一失败整体回滚）；应付/应收仍按约定表直写
  （fin_payable / fin_receivable，结算归 finance 模块）；
- org/equipment 模块的裸 SQL 库存操作保留（无批次表单，钉死 batch_no='' 与汇总行语义兼容）；
- 委外 biz_type 并入 PROD_USE/PROD_IN（InvBizType 枚举不含 OUT_USE/OUT_IN），
  历史 OUT_USE/OUT_IN 流水不受影响。

## 3. 前端架构

```
React 18 + TS(strict) + Vite 5
├── 路由: react-router 6 数据路由，懒加载，登录守卫
├── 状态: 服务端态 TanStack Query / 客户端态 Zustand
├── UI:   AntD 5(高密度ERP组件) + Tailwind(布局工具类)
├── 动效: Framer Motion —— 路由转场(渐入上移) / 指标卡错峰入场 / hover微交互
└── 图表: Recharts 驾驶舱
```

视觉定位：**专业 ERP 蓝色调（#1668dc）+ 现代动效点缀**。原则：动效服务信息理解（0.2~0.4s、ease-out），不做纯装饰动画，保持表格/表单的高信息密度。

## 4. 部署架构（目标态）

```
浏览器 ─→ Nginx(静态+反代) ─→ erp-server(8080, 集群可横向扩)
                                   ├→ MySQL 8(主从)
                                   └→ Redis 7(哨兵)
```

## 5. 与金蝶/用友的功能对标清单

| 域 | 金蝶K3/用友U8 | 本系统模块 | 阶段 |
|---|---|---|---|
| 财务 | 总账/应收应付/固定资产/成本 | erp-finance | P2 |
| 供应链 | 采购/销售/库存/存货核算 | purchase/sales/inventory | P1 |
| 生产 | BOM/MPS/MRP/生产订单/车间/委外 | erp-mrp | P3 |
| 基础 | 物料/客商/仓库/计量单位 | erp-basedata | P1 |
| 组织 | 用户/角色/部门/岗位/权限 | erp-system | P0 |
| 决策 | 报表/驾驶舱 | dashboard(前端聚合) | P1+ |

（阶段为开发批次，**全部实现**，非 MVP 裁剪。）
