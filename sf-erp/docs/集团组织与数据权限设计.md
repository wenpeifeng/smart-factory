# 集团组织与数据权限设计

> 版本：v1.2（2026-09-06 S1/S2 落地：租户插件 + 组织上下文 + 数据范围三档 + 全表迁移） · 状态：租户/组织基座已上线（见第 7 章落地状态） · 关联：docs/modules/org.md（多组织业务）

## 0. 租户体系（v1.1 新增）

**tenant_id（租户）与 org_id（组织）是两个隔离维度，同时具备：**

| | tenant_id | org_id |
|---|---|---|
| 回答 | 这是谁家的数据（商业边界） | 集团内哪个组织的数据（权限边界） |
| 隔离强度 | 绝对（MP TenantLineInnerInterceptor 自动 WHERE tenant_id=?） | 按数据范围五档（DataScopeInterceptor） |
| 对标 | 金蝶云星空 SaaS 账套隔离 | 金蝶 EAS 多组织数据权限 |

**落库规则**：全部业务表 `tenant_id NOT NULL DEFAULT 1000`（存量归默认租户）；
隔离表（单据/库存/财务）另加 org_id（业务数据回填 1=总厂），共享表（物料/客商/科目/BOM/菜单/字典/流程定义/工厂档案）org_id=0；
租户内无组织语义的系统/流程运行时表（sys_role、wf_task 等）org_id 也为 0（列仅为 BaseEntity 映射兼容）；
唯一键按租户撞键评估调整（sys_user 的 uk_username 已改为 username+tenant_id），业务单据号自带唯一性不动。sys_user 加 tenant_id（租户+账号定位用户）。
历史脚本不可改（Flyway 校验），以 V10xx 新迁移统一落地 —— 新环境一遍迁移得到同等结构。
**已落地**：V1011（sys_tenant 建表+默认租户种子）、V1012（98 张表幂等 ADD tenant_id/org_id + sys_user data_scope + uk 重建，2026-09-06 执行成功）。
**新表规范**：BaseEntity 已映射 tenant_id/org_id，**新建表必须包含这两列**（tenant 默认 1000 / 共享表 org 0 / 隔离表 org 1），否则实体查询直接报未知列。

## 0.1 三门户架构（v1.1 新增，对标金蝶云星空/用友 YonBIP）

```
登录页（分屏式现代设计 + 两步式：账号密码 → 租户/组织选择）
  ├─ 业务门户 /        95% 用户：驾驶舱 + 供应链/财务/生产菜单（按权限动态渲染）
  ├─ 管理门户 /admin/* 平台管理员/集团IT：租户/组织/用户/角色/菜单/字典/审计
  └─ 移动门户 /m/*     仓库 PDA 扫码作业（已交付）
```

- 一套系统多布局：同一 SSO 认证、同一权限体系；菜单按 portal 标识（BIZ/ADMIN）分流到 MainLayout / AdminLayout
- 租户管理员只管本租户；平台超管跨租户；多组织用户顶栏组织切换器（切换重签上下文，数据自动过滤）
- 登录页风格：左品牌区（深色渐变+动态数据元素+价值点）+ 右玻璃拟态登录卡，Framer Motion 编排入场/聚焦/错误抖动微交互，湛蓝专业色系

## 1. 权限三层模型（对标金蝶 EAS）

```
┌─────────────────────────────────────────────┐
│ L1 功能权限 RBAC（一期已交付）                  │
│    角色 → 菜单 → 按钮权限点 → 接口注解校验        │
├─────────────────────────────────────────────┤

│    用户.数据范围 → SQL 行级自动过滤              │
├─────────────────────────────────────────────┤
│ L3 字段权限（简化版）                          │
│    角色敏感字段（成本价/工资）→ VO 序列化过滤     │

```

## 2. 组织架构模型

```
org_org（组织树：类型 GROUP集团/COMPANY公司/FACTORY工厂）
  ├─ 集团「XX控股」
  │   ├─ 公司「XX智造」
  │   │   ├─ 工厂「苏州工厂」→ base_warehouse.factory_id
  │   │   └─ 工厂「东莞工厂」
  │   └─ 公司「XX贸易」
```

- 仓库/工厂归属由 erp-org 模块管理（V96x），本设计补齐上层的集团/公司层级与用户绑定。
- `sys_user` 增加 `org_id`（主归属组织）+ `data_scope`（数据范围枚举）。

## 3. 数据范围（五档，金蝶同款）

| 枚举 | 含义 | SQL 注入条件 |
|---|---|---|
| ALL | 全部数据 | 不注入 |
| ORG_AND_CHILD | 本组织及下级 | `org_id IN (当前组织及递归子组织)` |
| ORG_ONLY | 仅本组织 | `org_id = 当前组织` |
| DEPT_ONLY | 仅本部门 | `dept_id = 用户部门 AND org 条件` |
| SELF | 仅本人 | `create_by = 当前用户` |

## 4. 技术实现（业务代码零侵入）

1. **组织上下文（已落地）**：`erp-framework` 的 `OrgContextHolder`（ThreadLocal：tenantId/orgId/dataScope/userId），JwtAuthFilter 从令牌 claims（登录/切换组织时签入）+ 用户档案加载写入，请求结束 finally 清理；无上下文时默认 tenant 1000 / org 1 / 不注入数据范围。多组织用户顶栏「组织切换器」→ `GET /auth/switch-org/{orgId}` 重签令牌。
2. **MyBatis-Plus 双拦截器**（`erp-framework`，拦截器链顺序：租户 → 数据权限 → 分页）：
   - **多租户**：`TenantConfig` + `TenantLineInnerInterceptor`，所有 SQL（含 XML 手写）自动 `WHERE tenant_id=?`、INSERT 补租户列；共享表白名单跳过（base_*、sys_menu、sys_dict_*、wf_definition、fin_subject、org_factory、mrp_bom(_item)、sys_tenant）；
   - **数据权限**：`DataScopeInnerInterceptor`（extends BaseMultiTableInnerInterceptor，JOIN 场景带表限定名防歧义），对组织隔离表（pur_/sal_/inv_/fin_/mrp_/qc_/cost_/ast_/eqp_/hr_ 各业务表 + sys_user）注入 org 条件；super_admin 角色（ROLE_ 前缀 authority）绕过；`@InterceptorIgnore(dataPermission="true")` 为跨组织报表逃生门；
   - 组织树缓存 Redis（变更时失效），子组织 ID 集合一次查询 —— 当前 OrgTreeProvider 因组织模型为 org_factory 平铺结构返回自身集合（TODO）。
3. **表改造（已落地）**：V1012 全表 ADD tenant_id/org_id，隔离表存量归 org=1（总厂），共享表 org=0；写入自动填充（MetaObjectHandler：tenantId=当前租户，orgId 按表语义 0/当前组织，显式赋值优先）。
4. **接口行为**：查询自动过滤；**写入自动填充 tenant_id/org_id**（与 create_by 一同注入），杜绝越权写。登录响应携带 tenantId/orgId/可切换组织列表；`/auth/me` 同步令牌上下文。
5. **字段权限（简化，S3 未动）**：`@Sensitive(roleKeys...)` 注解 + Jackson 序列化器，无权限角色该字段输出 null（成本价、工资额应用它）。
6. **分页排序规范（已落地）**：`PageQuery` 基类（pageNum/pageSize/sorts: List<SortField(field,direction)>），`PageUtils.applySorts/buildOrderBy` 按实体真实属性名白名单转 ORDER BY（蛇形列名仅由框架生成，非法字段忽略 + log.warn 防注入）。

## 5. 边界与约束

- 组织间数据**物理同库逻辑隔离**（共享物料/客商主数据，隔离单据与库存）——与完整集团版（多账套/内部往来/合并报表）的差距见 docs/modules/org.md 评估章节；
- 逻辑删除 + 数据权限 + 乐观锁三者叠加时，拦截器条件以 AND 组合，单测覆盖组合场景；
- 超管（super_admin）绕过数据权限，便于运维。

## 7. 落地状态明细（v1.2，2026-09-06）

**代码（erp-framework / erp-platform-system）**
- `BaseEntity`：+tenantId/orgId（INSERT 自动填充）—— 全实体新表必须带这两列；
- `context/OrgContextHolder`：ThreadLocal 租户/组织上下文（framework 层，JwtAuthFilter 写入/清理）；
- `config/TenantConfig`：TenantLineInnerInterceptor 装配 + 共享表白名单（tenant 忽略 + org 填 0 判定）；
- `mybatis/DataScopeInnerInterceptor` + `DataScope` 枚举 + `OrgTreeProvider` SPI：三档数据范围 SQL 注入（SELECT），DEPT_ONLY/SELF 留 TODO；
- `mybatis/PageQuery`（pageNum/pageSize/sorts）+ `PageUtils`：排序白名单转换（驼峰/蛇形属性名，非法忽略 + warn）；
- 登录链路：LoginForm 可选 tenantId、LoginVO 含 tenantId/orgId/orgs、`GET /auth/switch-org/{orgId}` 重签令牌、`/auth/me` 带令牌上下文、JWT claims 签入 tenantId/orgId、角色以 ROLE_ 前缀入 authorities（super_admin 绕过数据权限）；
- sys_tenant 租户 CRUD（管理门户 `/system/tenants`），默认租户 1000 保护不可停用/改码。

**SQL（script/sql/migration）**：V1011（sys_tenant + 种子）、V1012（98 张业务表幂等 ADD tenant_id/org_id；sys_user 另加 data_scope 并重建 uk_username 为 (username, tenant_id)）。重复启动 Flyway 校验通过（幂等）。

**已知妥协 / 遗留**
1. OrgContextHolder 物理位置在 erp-framework（而非 platform-system）：依赖方向约束（MybatisPlusConfig/拦截器在 framework 读，system 写），语义归属不变；
2. system 模块 OrgDirectoryMapper 只读直查 org_factory（erp-biz-org 的表）：依赖方向无法反向调其 Service，org_org 落地后应下沉为 framework SPI 正式实现；
3. ORG_AND_CHILD 暂等价 ORG_ONLY（org_factory 无父子层级），OrgTreeProviderImpl 留递归 TODO；
4. 可切换组织列表暂为全部启用组织（用户-组织绑定表未建，防越权依赖登录页/前端约束），待 sys_user_org 绑定后收紧；
5. dataScope/角色码 Redis 缓存 10 分钟（auth:scope:{userId} / auth:roles:{userId}），变更最迟 10 分钟生效；
6. 新增表（budget_* 由并行任务、fin_book 已补列）建表必须含 tenant_id/org_id，详见第 0 章"新表规范"。
