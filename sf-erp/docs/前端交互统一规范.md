# 前端交互统一规范（商业级一致性标准）

> 适用于全站所有页面。新页面开发与旧页面重构一律遵守；评审时按本规范逐条核对。
> 原则：**成熟组件库优先（AntD 5），公共封装次之，禁止页面级自造轮子。**

## 1. 公共组件层（src/components/）—— 必须使用，禁止绕过

| 组件 | 替代的重复代码 | 用法 |
|---|---|---|
| `PageHeader` | 各页面自写 `<Title>` | 所有内容页顶栏：`<PageHeader title="采购订单" subtitle="..." extra={<Button/>}/>` |
| `PageTable` | 每页重复的分页/loading/请求逻辑 | 所有分页列表：传 `url/queryKey/columns/params`，翻页不闪空 |
| `StatusTag` | 各模块自写状态颜色映射 | 所有状态展示：`<StatusTag value={text}/>`，语义色全站唯一 |

## 2. 公共 Hooks（src/hooks/）

| Hook | 场景 |
|---|---|
| `useDebounce` | 搜索输入防抖（300ms），防抖值进 queryKey |
| `useSubmitting` | **所有写操作按钮**：loading 禁点 + 未返回忽略重复调用 + 统一成功提示 |

## 3. 列表页模板（全站统一结构）

```
PageHeader（标题+主操作按钮）
└─ Card
   ├─ 工具栏：Input.Search(防抖) / Select 筛选 / 重置按钮（左），批量操作（右）
   └─ Table（PageTable 提供）：列按 ERP 高密度（列宽收紧、数字右对齐、长文本 ellipsis+Tooltip）
操作列固定右侧：详情(Drawer) / 编辑(Modal，仅草稿态可点) / 审核(Popconfirm) / 删除(Popconfirm 危险)
```

## 4. 表单规范

- 新增/编辑统一 Modal（≤7 个字段）或 Drawer（主子表/复杂表单）；
- 提交按钮必须挂 `useSubmitting`；校验消息具体（"请输入联系电话"而非"必填"）；
- 金额输入 `InputNumber` 精度 2、数量精度 4，禁止自由文本；日期用 RangePicker；
- 主子表编辑：子表用可编辑 Table，行删除即时生效，底部合计行实时计算。

## 5. 反馈与动效

- 成功/失败提示走 `App.useApp().message`（useSubmitting 已内置）；
- 危险操作（审核/删除/关闭/红冲）必须 Popconfirm 二次确认，确认文案写清后果；
- 动效只用两处：路由转场（MainLayout 内置）与图表入场（Framer Motion ≤0.4s）；**表格/表单内不加动效**（ERP 效率优先）；
- 空态用 AntD Empty + 引导文案（"暂无数据，点击右上角新增"）。

## 6. 后端配套（已就绪，写操作按需标注）

- `@Idempotent`：防重复提交（审核/提交类接口 5 秒窗口，业务异常自动放行重试）；
- `@RateLimit`：重查询接口限流（统计/报表类默认 10 秒 20 次，按用户维度）。

## 7. 一致性红线（评审必查）

1. 同类功能交互一致：所有"审核"都是 Popconfirm+按钮 loading；所有列表筛选都防抖；
2. 状态颜色只能来自 StatusTag 语义表，禁止页面自定颜色字符串；
3. 单据状态机按钮可见性：草稿才可编辑/删除，已审核只读，规则全站一致；
4. 日期/金额/数量格式全站统一（dayjs 'YYYY-MM-DD HH:mm:ss' / 千分位 + 2 位小数）。
